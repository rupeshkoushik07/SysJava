\paragraph*{Native methods (JNI)}
\sysname's bytecode analysis found 612 native methods (Java methods declared \texttt{native}, in the application and the JDK) and mapped 583 of them to C functions: 264 in libtcnative-1.so.0.2.28, 132 in libjvm.so, 88 in libjava.so, 67 in libj2pkcs11.so, 23 in libzip.so, 5 in libsunec.so, 2 in libmanagement.so and 2 in libnet.so (451 through JNI symbol naming, 93 through RegisterNatives tables, 39 through JVM native-method tables). Of the other 29, 20 are Windows-only, 4 have no matching function in any library, 4 are handled inside the JVM (intrinsics) and 1 could not be resolved. Apache Tomcat 7.0.109 is an older application on JDK 8 and binds native code only through classic JNI.

\paragraph*{How the syscalls were counted}
At runtime the JVM loaded 22 native libraries (sysdig trace). The mapped functions fall in 8 libraries: 7 of those, plus libj2pkcs11.so, which is not loaded at all. For each library, SysPart builds a call graph and collects every syscall reachable from the start functions: with binding, the functions the native methods map to; without binding, every function in the library, since without the mapping any of them could be called. Both use the same library files and SysPart build. The last row adds up the start functions and counts each syscall once.

\paragraph*{Result}
Across the 8 libraries, starting from the mapped functions reaches 116 syscalls; starting from every function reaches 124. Per library, the gap is largest in libjvm.so (+16), libjava.so (+10) and libnet.so (+9). Reached only without binding (8): \texttt{clock\_getres}, \texttt{fchdir}, \texttt{fsync}, \texttt{getppid}, \texttt{rt\_sigsuspend}, \texttt{socketpair}, \texttt{times} and \texttt{umask}.
