\paragraph*{Native methods (JNI)}
\sysname's bytecode analysis found 269 native methods (Java methods declared \texttt{native}, in the application and the JDK) and mapped 263 of them to C functions: 92 in libtcnative-2.so.0.0.14, 88 in libjvm.so, 69 in libjava.so, 9 in libzip.so and 5 in libnet.so (175 through JNI symbol naming, 48 through RegisterNatives tables, 40 through JVM native-method tables). Of the other 6, 5 have no matching function in any library and 1 could not be resolved.

\paragraph*{FFM downcalls}
Apache Tomcat 11.0.22 also calls native functions directly through the Foreign Function \& Memory (FFM) API in tomcat-coyote-ffm.jar. \sysname found downcall handles for 200 native functions, separate from the 269 native methods, and mapped 182 of them to the libraries that define them: 107 in libcrypto.so.3 and 75 in libssl.so.3. The other 18 (e.g. \texttt{EVP\_PKEY\_base\_id}, \texttt{EVP\_PKEY\_bits}) are not exported by these libraries. \sysname found no JNA or JNR-FFI bindings.

\paragraph*{How the syscalls were counted}
All 7 libraries are among the 20 native libraries the JVM loaded at runtime (sysdig trace). For each library, SysPart builds a call graph and collects every syscall reachable from the start functions: with binding, the functions the native methods and FFM downcalls map to; without binding, every function in the library, since without the mapping any of them could be called. Both use the same library files and SysPart build. The last row adds up the start functions and counts each syscall once. For libjava.so, libjvm.so, libnet.so and libzip.so, the binding numbers come from the \sysname pipeline's own run (same start functions; where both were computed, they agree).

\paragraph*{Result}
Across the 6 libraries with both results, starting from the mapped functions reaches 116 syscalls; starting from every function reaches 127. Per library, the gap is largest in libcrypto.so.3 (+24), libssl.so.3 (+16) and libjava.so (+8). Reached only without binding (11): \texttt{accept}, \texttt{chmod}, \texttt{fsync}, \texttt{getppid}, \texttt{listen}, \texttt{mlock}, \texttt{mlock2}, \texttt{rename}, \texttt{sendmsg}, \texttt{statfs} and \texttt{utimensat}.

\paragraph*{Why libjvm.so is not resolved without binding}
With binding, SysPart starts from its 88 mapped functions and resolves 104 syscalls. Without binding, it has to start from all 52,680, and it ran out of memory (\texttt{std::bad\_alloc}) at a 35 GB and again at a 60 GB limit. SysPart links every indirect call site to every address-taken function in the code the graph covers: 23,969 functions with binding, but all of libjvm.so without, whose 37,884 indirect call sites and at least 21,679 address-taken functions make about 800 million edges. The last row leaves libjvm.so out; with binding it adds no syscall the other libraries do not already reach.
